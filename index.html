Where can the file live?
  • On any host that gives it a public https:// address and allows cross-origin requests (CORS). Free ones that do, tested: Dropbox with one edit to the link, a GitHub repository, Zenodo, Backblaze B2. Google Drive and OneDrive share links do not.
  • Large packages start faster on a host that answers Range requests; without them the whole file downloads first, which still works.
  • The player fetches the file straight from your host in your browser. Embed My never receives or keeps it.

    Privacy and security Troubleshooting

    What a snippet does on your page

    An iframe is a window onto another site, and the browser keeps what runs in it apart from your page. Here is what that means for this snippet, and where it stops. Whether that is enough for your page is your call.

    • The activity runs on Embed My's own address, not on your site. H5P packages contain JavaScript. Inside the frame it cannot read your site's cookies, logins or storage, or touch your page's content. The snippet grants the frame one permission, fullscreen: no camera, microphone or location.
    • One script runs on your page, and it is sixty lines. The iframe is only a window. The h5p-resizer.js line is the one piece of code the snippet runs on your page itself: it sets the frame's height when the frame reports it, nothing else, and you can read it. Leave it out and the frame keeps the minimum height.
    • No cookies, no tracking, no learner records. The frame loads no analytics and reports to no one. Answers are not saved anywhere, so a reload starts the activity over. The browser caches the package's files and address so it loads faster next time; it keeps nothing about the learner.
    • The frame tells your page one thing. Its height, so the sizing script can fit it. Answers, scores and statements stay inside the frame.
    • Open source, both halves. The player is h5p-offline-player (MIT), the H5P runtime inside it is GPL-3.0, and this site is on GitHub. Anyone can read what runs.

    What the frame cannot protect you from

    • A package you do not trust. Its scripts run inside the frame as they would on any H5P site: it can load outside content it names, such as a YouTube video or a web font, and send what it collects there anywhere. After a click inside the activity it could even send the visitor's whole tab to another address, which browsers allow any iframe. Embed only packages you would run as a script on your own site.
    • Packages embedded on the same site share the frame's storage there: one package's scripts can read another's files and address.
    • The package link is public in your page's HTML. Never use a secret or expiring link, and keep personal data out of the package.
    • The frame and the script come from Embed My, on GitHub Pages. GitHub receives each visitor's IP address and your page's address, and the package host receives the IP address too. Check your organisation's data-protection rules before using a snippet on its pages.

    Questions people ask

    If it plays here, will it play in my LMS?

    Very likely, not certainly. The player runs the standard H5P runtime with the H5P hub's current libraries. Moodle, WordPress or another LMS may run older library versions or changes of their own, and a package made for one site can need a library only that site has. A failure here is the more useful result: a link the browser cannot reach, a package that is not an archive, or libraries that nobody serves will fail in most places.

    Where do I get an .h5p file?

    From wherever the activity was made. Lumi, H5P.com, h5p.org and the H5P plugins for Moodle, WordPress and Drupal all offer a download, usually under the activity's Reuse button.

    Exports from H5P.com and h5p.org often hold only the content and rely on the site they came from. Those play here too: the player keeps the H5P hub's libraries and adds them as the activity loads. Check the file in the preview above. Packages and library files →

    Can the file live on Google Drive, Dropbox or OneDrive?

    Dropbox, yes, with one edit to the share link: replace www.dropbox.com with dl.dropboxusercontent.com and dl=0 with dl=1. The unedited link redirects without the header a browser needs (CORS).

    Google Drive and OneDrive, no. Their links send the file without that header, and there is no setting to add it. A free GitHub repository, Zenodo or Backblaze B2 all work instead. Free places to put the file →

    Is there a maximum file size?

    Not from Embed My, which never holds your file. The player reads the package in place: it fetches the archive's index with a few kilobytes, pulls only what the activity asks for, and never holds more than 8 MB in memory. On a host that answers Range requests, as GitHub Pages does, a 300 MB package starts within seconds; what limits you there is your host and your visitors' connection.

    On a host without Range requests the whole file downloads and is stored in the browser before anything plays, and a package larger than the browser allows fails with a storage error. That allowance varies by browser and is smaller inside another site's page, so keep packages there to tens of megabytes, or move to a host that supports ranges. Hosts have caps of their own too: GitHub refuses single files over 100 MB.

    Big packages are big because of video. Run the package through h5p-normalize once and the video starts before the file has finished downloading. How big can a package be →

    Which browsers and devices does it work on?

    Current Chrome, Edge, Firefox and Safari, on desktop and on phones. The built-in browsers inside some social and messaging apps cannot run the player; open this page in a regular browser instead.

    Does it check accessibility?

    Keyboard and screen-reader behaviour come from the H5P content type and from how the activity was authored, and this check does not test them. Run through the activity here with the keyboard alone, and check that video and audio have captions or a transcript.

    Can an AI assistant check a package for me?

    Yes. The player's repository ships agent skills for Claude Code, Cursor, Copilot, Codex and the rest. h5p-verify plays a package in a real H5P runtime in a headless browser and reports start-up, errors, missing libraries and a screenshot: the same check as this page, without a link. Two companions make a package's video start at once, and put the player on a site of your own.

    npx skills add missing-elements/h5p-offline-player --skill h5p-verify
    Can I use a snippet on a school or company site?

    Ask whoever looks after data protection there first, and expect a no. Each visitor's browser contacts GitHub when the page opens, and stores the player's files on the device. Embed My is a free tool, not a company, so there is no data-processing agreement to sign.

    Checking a package here is different: only you open this page, and the package goes from its host to your browser. For an organisation's own pages, run the player on a domain it controls.

    Something else? See the troubleshooting guide, or ask on GitHub.
